# Integration tests

Every integration test is a module of one test binary, `tests/integration/main.rs`. Cargo links each top-level file in `tests/` as its own executable, and each carries the whole backend, so new tests go under `tests/integration/` as modules rather than as new top-level files. PostgreSQL cases live under `tests/integration/postgres/`, are `#[ignore]`d, and are selected by module path: `cargo xtask db-integration` runs `postgres::` except the rollback cases, and `cargo xtask migration-rollback` runs those serially. Both build with the same package and feature selection as `cargo xtask unit`, so they reuse its binary. A unit test in `tools/xtask` fails if a module file is not declared in its `mod.rs` or a rollback selection names no existing case.

`postgres::minecraft_waypoints` covers public readback, database-current administrator authority, denied mutations after demotion, authority leases held through blocked waypoint commits, UUIDv7 generation, concurrent 256-marker capacity, cross-world moves, and PostgreSQL name/slot constraints. Its guarded rollback/reapply case runs serially through `cargo xtask migration-rollback`; the other cases run through `cargo xtask db-integration`.

`postgres::account_owner_deletion` proves that final-owner self-deletion preserves identity, authority, and sessions; deletion succeeds with another active owner; and concurrent deletions or deletion racing with owner demotion preserve one active owner through database locking. It is included in `cargo xtask db-integration`.

`postgres::live_chat_moderation` covers database-current superuser authority, content erasure, idempotent deletion, tombstone pagination, demotion, and deleted-account rejection. It is included in `cargo xtask db-integration`.

`postgres::live_chat_runtime` covers automatic bans stored per IPv6 /64 with a 24-hour expiry, room-scoped recent history, exact row-comparison keyset pages over tied timestamps and tombstone cursors, and idempotent closing of call and participant rows left open by a previous process. It is included in `cargo xtask db-integration`.

`postgres::i18n_sources` synchronizes all eight embedded UI catalogs, verifies complete per-locale readback through cold database read-through and the refreshed RAM cache, and confirms repeated synchronization preserves row identifiers without duplicates, rewrites only a drifted row, and writes nothing when the catalogs match. It is included in `cargo xtask db-integration` and uses the same isolated PostgreSQL 18 lifecycle described below.

The PostgreSQL cases create isolated databases on the server named by `TEST_DATABASE_URL`, apply embedded migrations, execute ignored lifecycle cases, and force-drop each database afterward. The URL must connect to PostgreSQL 18 and select the database named exactly `cyhdev_test_maintenance`; loopback TCP is accepted, and a Unix socket URL must identify its directory explicitly, for example `postgresql://postgres@localhost/cyhdev_test_maintenance?host=%2Frun%2Fpostgresql`. The root xtask validates the same conditions through `psql` before invoking Cargo. Remote servers are always refused. `postgres::account_boundaries` covers persisted credentials and roles, session propagation and revocation, and migration rollback/reapply. `postgres::account_lifecycle` covers immediate session and login revocation, private retention, generic public identity primitives, authored post/comment/photograph/chat preservation, vote rows and denormalized totals, system-actor protection, premature hard-purge rejection, idempotent due hard purge and profile-cleanup finalization with a permanent users tombstone, and migration rollback/reapply. `postgres::account_oidc` proves that provider email cannot auto-link a local account, issuer-subject ownership is unique, unlink removes login authority, and only an explicitly linked active verified account resolves. `postgres::forum` covers explicit linking-independent authority, repeated-author projections, transactional reply counts and fanout, tied keysets, optimistic revisions, database-current moderation permission, retained authored content, deleted-author masking, and private inbox/subscription removal. `postgres::account_verification` covers one-time, expired, and future-created verification tokens and proves that a second signup for an unverified email replaces its password, name, and verification link and revokes its sessions, that verified accounts stay unchanged, and that verification revokes earlier sessions. `postgres::account_oidc_reset` proves that a password reset removes linked provider identities and sessions and that link receipts distinguish new links. `postgres::account_migrations` rewinds to just before the September 23 account migrations and proves that case-insensitive identity refuses colliding rows and that token digests hash existing token text; it runs serially with the rollback coverage. `postgres::migration_guards` rewinds by explicit migration version and proves that lifecycle, OIDC, retention-notification, authorization-audit, and forum state prevents destructive rollback. `postgres::cache_consistency` proves committed blog metadata/search publication and explicit i18n cache refresh against PostgreSQL. `postgres::photography_invariants` covers concurrent vote recount serialization and denormalized totals. `postgres::wasm` proves that public module metadata keeps retained content while masking a deleted owner's stable UUID. `postgres::retention_notifications` covers independent seven-day and 24-hour stages, durable exponential retry, stable notification identity, overlapping claim exclusion, retained-email revalidation, and audit-row preservation after hard purge cancellation. `postgres::authorization_admin` covers database-current authority, role-session refresh, permission binding reads, privacy-safe audit display names, audit mutation guards, self-lockout, last-owner preservation, and competing owner demotions. `postgres::profile_picture_history` covers the eight-picture cap, one-active-row invariant, selection, active fallback after deletion, durable cleanup rows for pruned and explicitly deleted media, bulk retry idempotency, and retry-generation preservation. `postgres::runtime_bounds` covers the visitor-board migration backfill (skipping invalid coordinates and merging signed zeros), flushes that insert raw visit rows and board counts in one transaction, and the statement, lock, and idle-in-transaction timeouts that apply to pooled sessions but not to the migration connection.

These cases are intentionally not executed during implementation waves. Wave 8 runs the database suite through the root review commands with an explicit PostgreSQL 18 maintenance URL; the lifecycle migration test must run serially with other rollback coverage.
