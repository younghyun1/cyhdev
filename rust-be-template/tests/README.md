# Integration tests

The PostgreSQL integration binaries create isolated databases on the server named by `TEST_DATABASE_URL`, apply embedded migrations, execute ignored lifecycle cases, and force-drop each database afterward. The URL must connect to PostgreSQL 18 and select the database named exactly `cyhdev_test_maintenance`; Unix sockets and loopback servers are accepted by default. The root xtask validates the same conditions through `psql` before invoking Cargo. A remote CI database additionally requires both `CI=true` and `TEST_DATABASE_ALLOW_REMOTE_CI=1`. `postgres_account_boundaries` covers persisted credentials and roles, session propagation and revocation, one-time email verification, expired and future-created verification-token rejection, and migration rollback/reapply. `postgres_account_lifecycle` covers immediate session and login revocation, private retention, generic public identity primitives, authored post/comment/photograph/chat preservation, vote rows and denormalized totals, system-actor protection, premature hard-purge rejection, idempotent due hard purge and profile-cleanup finalization with a permanent users tombstone, and migration rollback/reapply. `postgres_account_oidc` proves that provider email cannot auto-link a local account, issuer-subject ownership is unique, unlink removes login authority, and only an explicitly linked active verified account resolves. `postgres_forum` covers explicit linking-independent authority, repeated-author projections, transactional reply counts and fanout, tied keysets, optimistic revisions, database-current moderation permission, retained authored content, deleted-author masking, and private inbox/subscription removal. `postgres_migration_guards` rewinds by explicit migration version and proves that lifecycle, OIDC, retention-notification, authorization-audit, and forum state prevents destructive rollback. `postgres_cache_consistency` proves committed blog metadata/search publication and explicit i18n cache refresh against PostgreSQL. `postgres_photography_invariants` covers concurrent vote recount serialization and denormalized totals. `postgres_wasm` proves that public module metadata keeps retained content while masking a deleted owner's stable UUID. `postgres_retention_notifications` covers independent seven-day and 24-hour stages, durable exponential retry, stable notification identity, overlapping claim exclusion, retained-email revalidation, and audit-row preservation after hard purge cancellation. `postgres_authorization_admin` covers database-current authority, role-session refresh, permission binding reads, privacy-safe audit display names, audit mutation guards, self-lockout, last-owner preservation, and competing owner demotions. `postgres_profile_picture_history` covers the eight-picture cap, one-active-row invariant, selection, active fallback after deletion, durable cleanup rows for pruned and explicitly deleted media, bulk retry idempotency, and retry-generation preservation.

These cases are intentionally not executed during implementation waves. Wave 8 runs the database suite through the root review commands with an explicit PostgreSQL 18 maintenance URL; the lifecycle migration test must run serially with other rollback coverage.
