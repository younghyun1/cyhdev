## Scope and design

Use the pinned in-process Pumpkin climate sampler for bounded, zoom-dependent tiles. Research an efficient surface climate projection rather than generating chunks. Keep large-biomes behavior, Nether and End generation, permissions, binary plus gzip, optional PNG, and the shared 512 MiB cache budget.

Carry sampling semantics through nullable Y in API requests, responses, binary metadata, server and browser cache identities, and hover receipts. Preserve existing numeric-Y requests and their CYBM version 1 encoding. Surface requests use null and version 2 with an Overworld-only signed Y sentinel, without increasing frame size. Make the browser explicitly request surface mode by default in the Overworld, with a compact slice selector and Y control for underground inspection. Other dimensions keep numeric sampling.

The actual/predicted terrain boundary must hide during zoom and return at the completed zoom geometry. Same-zoom panning must keep it visible. Tie visibility to Leaflet's zoom lifecycle, with separate regressions for zoom and pan.

[Cubiomes' `SAMPLE_NO_DEPTH`](https://github.com/Cubitect/cubiomes/blob/master/biomenoise.h) supplies a distinct, cheaper projection: [the sampler](https://github.com/Cubitect/cubiomes/blob/master/biomenoise.c) initializes depth to zero and skips its vertical spline while retaining the other climate coordinates. Use that algorithm with the existing Pumpkin normal/large-biomes routers. This is a surface climate projection, not a claim that either viewer uses that flag as its default. Chunkbase's [seed map](https://www.chunkbase.com/apps/seed-map) remains a behavior reference; no inspectable implementation was found to attribute this algorithm to it.

The pinned Pumpkin 26.3 [biome tree](https://github.com/Pumpkin-MC/Pumpkin/blob/4426d1113a211e6018a2db416e33b6b8a7802614/assets/multi_noise_biome_tree.json) places lush, dripstone and sulfur caves at quantized depth 2000..9000 (0.2..0.9), and deep dark at 11000 (1.1); ordinary surface entries include depth zero. Its [cave-biome tag](https://github.com/Pumpkin-MC/Pumpkin/blob/4426d1113a211e6018a2db416e33b6b8a7802614/assets/datapack/data/c/tags/worldgen/biome/is_cave.json) contains those four biomes. Depth projection normally favors surface entries, but these depth intervals alone do not prove cave exclusion because selection minimizes distance across all climate dimensions.

Correction from the independent Paper 26.3 fixture: unfiltered depth-zero lookup still selected sulfur caves for two of 1,520 sampled rows. Surface mode therefore also requires a nearest non-cave candidate lookup when the first result is one of those four cave biomes. Keep the other climate coordinates, tree distance and tie ordering intact; skip cave leaves using bounded branch-and-bound traversal rather than replacing a cave with an arbitrary biome or scanning upward. The independent reference filters Paper's biome parameter list. Explicit fixed-Y slices retain the unfiltered lookup.

An exposed cave can still be the biome of real visible terrain. Surface projection deliberately does not predict that geometry. Likewise, Mojang describes sulfur caves as underground and [sulfur springs as separate features above them](https://feedback.minecraft.net/hc/en-us/articles/46690753273997-Minecraft-Java-Edition-26-2). A surface sulfur spring does not require a sulfur-cave-colored surface biome cell. Saved terrain and its observed biome remain authoritative where available; fixed-Y mode retains cave discovery.
