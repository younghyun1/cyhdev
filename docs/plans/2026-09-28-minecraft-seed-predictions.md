## Scope and ownership

The existing same-user Paper socket supplies the seed, effective preset, world identity, profile revision, and a complete bounded chunk-coverage receipt privately. Default and large-biomes Overworld generation use distinct Pumpkin routers. Unsupported dimensions, custom generation settings, or uncertain compatibility fail closed. Browser requests cannot override the world preset or obtain the seed.

The Rust backend launches the pinned worker with seed material on stdin, bounds input/output and concurrent work, applies a deadline, and terminates a cancelled child. The worker handles at most 1,024 biome samples per invocation. A RAM cache has a 512 MiB total budget, including 64 MiB index headroom and per-entry ownership, with a separate 65,536-entry cap and eviction. A palette and packed indices avoid repeated biome-string allocations. Keys include the world UUID, private generator revision, seed, effective preset, coordinates, and Y; the compiled worker revision is fixed for the process. Cached biome cells do not contain cached visibility decisions. A second Paper context read after either a cache hit or computation detects profile changes and refreshes coverage before filtering output.

The frontend adds an explicit 128-by-128-block fixed-Y preview. Predicted cells render only in chunks confirmed ungenerated, using muted styling and visible provenance. Complete coverage includes generated, ungenerated, unknown, and excluded states. Predictions expire after fifteen seconds and clear on dimension changes, hiding, original-map activation, and terrain refresh; actual observations additionally mask their chunks. A one-pixel dark perimeter with a two-pixel light casing separates predicted coverage, without an internal chunk grid. Edge cells fade inside permitted coverage only. This is a timed coverage snapshot, not an atomic live-world claim. Existing actual elevation, structures, and block search retain their meanings.

## Activation

Install the updated Paper plugin and the matching `minecraft-seed` executable with its license/notices, configure the existing `MINECRAFT_WORLD_SOCKET` and new absolute `MINECRAFT_SEED_WORKER` path, and deploy through the normal workflow. [Backend activation](../architecture/be/minecraft-explorer.md) and the [plugin build instructions](../../minecraft/map-control/README.md) specify the boundaries. Changing presets in `server.properties` does not override an existing world's effective generator; profile detection reads the live generator settings. Rebuild and restart the backend when replacing the worker so its in-memory cache cannot retain another engine's results. No production deployment, release build, or macOS runtime check was performed.
