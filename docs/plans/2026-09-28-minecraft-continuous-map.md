# Continuous Minecraft seed map

Status: complete for implementation and local verification, 2026-09-28. Replaced the single 128 by 128 block preview with a continuous, zoom-aware prediction layer beneath squaremap. Default and large-biomes support, hover inspection, the thin rendered-terrain boundary, and the maximum 512 MiB server prediction budget remain enforced. No live service stops, restarts, reloads, or installations occurred.

Checkout: `main` at implementation commit `7745858` (continuous tiles), following `d2c20a6` (private visibility profiles) and `18f9892` (function-only datapack compatibility). The starting checkout was clean and ahead of fetched `origin/main` (`e5c2608`) without divergence. Only this plan and its index remain to be committed in the handoff; no push or deployment was performed. Sillok objective: `01a0ea95-ad15-75a0-b40a-db3f0dab3e3b`.

Correction: the earlier bounded preview did not satisfy the intended map interaction. Its per-request process startup, two Paper coverage calls, shared one-second cooldown, single response state, and SVG-cell rendering prevent continuous loading. Pumpkin already exports an independently usable biome sampler; no Minecraft server instance or preview world is needed.

Implementation: reusable Pumpkin sampler on a dedicated bounded CPU worker inside the web backend; aligned 64 by 64 palette tiles with step `4 << level`; separate short-lived authoritative generator/visibility profile; independently bounded tile scheduling and caching; Leaflet canvas tiles retained across movement and zoom. Actual squaremap PNG alpha selects rendered terrain over the prediction base. It does not grant visibility permission: the private plugin profile separately supplies supported visibility geometry and the world border, and missing or unsupported policy rejects predictions. Generated-but-unrendered terrain can display explicitly predicted biomes until squaremap renders it.

Completed: the private plugin profile, sampler library, backend tile API/cache, generated contracts, browser tile lifecycle, and architecture/design documentation are implemented together. The browser retains canvas tiles during movement, prefetches neighboring tiles, refreshes permission-bearing responses before expiry, and caps concurrency and memory. Existing analysis, block searches and saved-structure queries retain their observation limits and cooldown. No database changes were made. Distribution notices now describe the backend's direct link to GPL-covered Pumpkin code.
