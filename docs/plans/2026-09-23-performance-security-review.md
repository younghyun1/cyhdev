## Fix first

1. **Pre-registration account takeover.** Login does not require a verified email (`features/accounts/repository/accounts.rs:34`). A second signup for an existing unverified email discards the new password and resends the verification link for the existing account (`features/accounts/api/signup.rs:71`, `features/accounts/service/registration.rs:66`). Verification then upgrades that account's live sessions (`features/accounts/service/verification.rs:46`, `features/accounts/service/session_service.rs:147`), which can start an OIDC link without a password; password reset does not remove links (`features/accounts/service/passwords.rs:93`). An attacker who registers a victim's email first keeps OIDC access after the victim verifies and resets. Fix: on a duplicate unverified signup, replace the stored hash and name (or delete the stale row) before sending the link; revoke sessions on verification; do not issue sessions to unverified accounts; expire unverified accounts; require password confirmation to start a link; revoke or flag links on password reset.
2. **Live-chat WebSocket accepts 64 MiB messages.** `features/live_chat/api/ws/upgrade.rs:76` never sets `max_message_size` or `max_frame_size`, so tungstenite defaults (64 MiB message, 16 MiB frame) apply before the 64 KiB protocol check. Guests can hold gigabytes with a few dozen sockets. Fix: `.max_message_size(64 * 1024).max_frame_size(64 * 1024)` plus `max_write_buffer_size`, as `features/minecraft/service/transport.rs:58` already does.
3. **A full chat rate table permanently bans legitimate senders.** When the 16,384-key table is full, `record_message_attempt_for_key` returns abnormal (`features/live_chat/service/cache/runtime_state.rs:54-61`), and the handler persists a ban with no expiry (`features/live_chat/api/ws/message_handler.rs:110`, `features/live_chat/repository/messages.rs:197`). Keys are exact IPs, so one IPv6 /64 fills the table; the 2-second `clear_stale_rate_windows` is never called. Fix: reject instead of banning when full, group IPv6 by /64, call the short cleanup, and give automatic bans an expiry.
4. **Deleting a comment deletes other users' replies.** `fk_comments_parent` and `fk_photograph_comments_parent` are `ON DELETE CASCADE` (`rust-be-template/migrations/2025-02-18-045958_posts_tables/up.sql:44`, `rust-be-template/migrations/2026-06-17-000000-0000_photograph_social/up.sql:45`), and owner deletes are hard deletes (`features/blog/repository/comments.rs:162`, `features/photography/repository/comments.rs:132`). Fix: `ON DELETE RESTRICT` in a new migration and tombstone updates, as the forum does.
5. **No request or database time bounds.** `init/server_init.rs:173` serves without a hyper timer, so hyper's header-read timeout is inactive; there is no body timeout, request timeout, connection cap, or SIGTERM flush. The pool is `physical_cores * 10` with no `statement_timeout`, `lock_timeout`, or `idle_in_transaction_session_timeout` (`server_init.rs:82-88`). Slow clients hold connections indefinitely and a lock wait can drain the pool. Fix: hyper timer with header-read timeout, `TimeoutLayer` and body timeout on non-WebSocket routes, a connection cap, an explicit pool size of about 20 to 30, and session timeouts in the pool URL only.

## Decisions

**Retention is policy.** Visitor rows, request logs, and server-side stored IPs are kept indefinitely by the owner's decision on September 23. Retention, truncation, and row coalescing are out of scope; performance work on these tables must keep every raw row.

**Guest IPs stay server side.** Decided September 23: remove guest IPs from every browser-facing format and use an opaque keyed hash for guest identity and nicknames. Stored IPs remain for bans, rate limits, and geo lookup. Original finding: Chat actor records, message history, the binary codec, and public `GET /api/live-chat/messages` all include `guest_ip` (`features/live_chat/api/rtc_signal.rs:41`, `dto/responses/live_chat/live_chat_message_response.rs:13`, `features/live_chat/api/binary_codec/writer.rs:106`). The original [live chat plan](live-chat.md) lists public guest IP display as a goal, but the browser never renders it and guest nicknames now exist. If display is no longer intended, remove the field from every wire format and derive guest keys and nicknames from a keyed hash of the IP. If it is intended, consider displaying a truncated prefix only.

## Security: medium

- **Realtime flooding.** Typing, heartbeat, media-state, and call signals have no per-connection rate limit; typing broadcasts the whole typing list to every client on each event, even without a change (`features/live_chat/api/ws/presence.rs:36`). One IP can hold all 4,096 chat slots with idle sockets, and the host-stats WebSocket is uncapped (`features/server_status/api/host_stats.rs:14`). Fix: token bucket per connection for all client events, broadcast typing only on change, per-IP and per-/64 connection caps, idle deadline, write timeout, encode each broadcast once.
- **Oversized photo social bodies.** Photograph comment and vote routes inherit the 150 MiB default limit (`routers/main_router.rs:8,316`), unlike blog (1 MiB) and forum (128 KiB). Fix: a 16 KiB route limit or the bounded JSON extractor.
- **Password-confirmation endpoints.** Profile update, account deletion, and OIDC unlink verify passwords without the auth throttle and share the 4-slot Argon2 semaphore with login, so any verified account can keep login at 429 site-wide, and a stolen cookie is an unthrottled password oracle. The borrowed permit (`features/accounts/service/account_service.rs:81-90`) is released on request cancellation while `spawn_blocking` Argon2 keeps running. Fix: throttle per user and IP, revoke after repeated failures, and move an owned permit into the blocking closure; the same permit pattern exists in `util/image/process_uploaded_image_files.rs:55-62`.
- **Same-origin embedded apps.** The Minecraft map and EU5 iframes use `allow-scripts allow-same-origin` on same-origin content (`pages/minecraft.tsx:11`, `pages/eu5_locations_db.tsx:105`), which lets framed script remove the sandbox and call the API as the viewer. The Squaremap directory is written by the game server's plugin. Fix: `Content-Security-Policy: sandbox allow-scripts allow-popups` on those responses, drop `allow-same-origin`, and compare `event.source` for EU5 `postMessage`; a separate origin is stronger.
- **No global browser security headers.** Only uploaded demos and Squaremap set CSP or `nosniff`; the SPA and API send no CSP, HSTS, `frame-ancestors`, or `Referrer-Policy`. CSP blockers: the inline theme script in `index.html` (hash it), inline `<style>` blocks in `pages/projects.tsx:469` and `pages/photographs.tsx:587`, Toast UI inline styles, and OSM/Nominatim origins.
- **Call join race.** Clicking Leave during the camera prompt resets state, but `joinCall` resumes after `requestUserMedia` and still sends `join` with live tracks (`state/rtc.tsx:204-262`). Fix: a join generation counter checked after each await.
- **RTC slow consumer (plausible).** Room fan-out and teardown await each subscriber's `renegotiate()` in turn (`features/live_chat/service/rtc/room.rs:166,222`), which waits on bounded queues that feed a socket write without a timeout. A participant who stops reading blocks teardown for others. Fix: `try_send` with teardown on full queues, per-peer renegotiation tasks, write timeout, and ignore answers without an outstanding offer.
- **Blog and photo comment abuse.** No write rate limit (the forum has one), and detail responses return up to 1,000 comments of up to 4,000 characters each (`features/blog/repository/comments.rs:21`, `features/photography/repository/photographs.rs:28`). Fix: reuse the forum limiter and add keyset comment pagination.
- **Case-sensitive identity uniqueness (plausible).** Email and user name uniqueness is exact-match (`rust-be-template/migrations/2026-08-30-000000-0000_account_identity_uniqueness/up.sql:37-39`) while the abuse limiter lowercases both. Fix: normalize on write and add `lower()` unique indexes after checking existing rows.

## Security: low

- OIDC `state` is not bound to the initiating browser, so a callback URL can log a victim into the attacker's account (`features/accounts/service/oidc/flow_store.rs:26`). Fix: a `__Host-` Lax nonce cookie whose hash is stored with the pending flow.
- Signup may reveal registered emails when both email and a taken user name are submitted: the email violation returns 202, the name violation 409 (plausible; depends on constraint check order).
- Auth abuse stores are one shared 16,384-entry map that rejects new keys when full, the OIDC pending store holds 512 flows, and sessions have no per-user cap; about 8,192 IPv6 /64s lock out new IPs for 24 hours.
- The per-identity login limit counts attempts before password verification, so five requests per 15 minutes lock any known email out of password login.
- Post-commit session revocation after password reset, deletion, verification, and role changes runs in the request future and is skipped if the client disconnects. Fix: spawn the commit and follow-up, then await the handle.
- Unverified sessions cannot log out because logout sits behind `auth_middleware`.
- Reset and verification tokens are stored raw; store a SHA-256 of a 256-bit token.
- Admin authority holds the global session read lock across Minecraft RPCs of up to 15 seconds, so a queued writer stalls all logins (`features/accounts/service/authorization.rs:27-38`).
- Public `/api/healthcheck/fastfetch` and `/api/healthcheck/state` expose hostname, kernel, local IP, and the PostgreSQL version; `/api/live-chat/cache-stats` is public although the cache policy calls it admin.
- `X-Forwarded-For` reads only the first header line (`util/extract/client_ip.rs:60`); use `get_all` and canonicalize IPv4-mapped addresses.
- Remote ICE candidates are not capped or filtered (`features/live_chat/service/rtc/peer.rs:123`).
- `image` is built with default features, and uploads sniff the format, so EXR, HDR, DDS, and other decoders are reachable (`rust-be-template/Cargo.toml:137`). Disabling unused codecs also removes the `exr` to `paste` chain.
- Batch uploads stage originals with full EXIF and GPS in a fixed, world-readable `/tmp/cyhdev-batch/` (`util/image/batch_pipeline.rs:10-17`); use a private `tempdir()`.
- Draft posts can surface in search if index removal fails, and drafts accept comments and votes (plausible).
- The scratch runtime image runs as root and has no `/tmp`, which `tempfile` needs; `.dockerignore` misses Playwright traces, the staged EU5 build, and local assistant files; wasm-pack downloads unverified tool binaries; image builds do not check submodule cleanliness; CI checkout keeps its token (`persist-credentials`).

## Performance

- **Blog view counter.** Each detail read runs `UPDATE posts SET post_view_count = post_view_count + 1` under a per-post stripe mutex (`features/blog/service/posts.rs:188-197`), and the unused `idx_posts_view_count` makes every update non-HOT. Reuse the photograph write-behind buffer and drop unused counter indexes (`idx_posts_view_count`, `idx_posts_total_*`, `idx_photographs_*`, `idx_comments_total_*`).
- **Forum topic list** selects full topic bodies for cards that show 300 characters (`features/forum/repository/reads.rs:42`); select `left(forum_topic_body, 301)`.
- **Keyset cursors as OR chains (plausible).** `a < x OR (a = x AND b < y)` in forum reads, notifications, and chat history cannot be used as an index range bound. Use row comparison and add `(room_key, message_created_at DESC, live_chat_message_id DESC)` for chat. Confirm with `EXPLAIN` on seeded data.
- **Startup scans.** The visitor board is rebuilt with a full `GROUP BY` over `visitation_data` at every start; maintain an aggregate board table in the flush transaction while keeping raw rows. Startup `recent_messages(50_000)` sorts all chat rows without a room filter.
- **Forum notification cleanup** deletes at most 512 rows per hour and ignores `remaining_expired`, while one reply can create 4,095 rows.
- **Tag identity exhaustion.** `tags.tag_id smallint` is consumed by `ON CONFLICT DO NOTHING` on every save (`features/blog/repository/posts.rs:192`); after about 32,000 tag upserts, tagged saves fail. Insert only missing names and widen to `integer`.
- **Photo gallery** recreates every card on each infinite-scroll page because segments are keyed by object identity (`pages/photographs.tsx:331,658`), and images have no intrinsic size; key by `seg.key` and add `aspect-ratio`. This likely explains the photographs CLS noted on September 21.
- **About pages** statically import all eight locales: 49 kB gzip for `/about` and 41 kB for `/about-blog`, about eight times what one visitor needs.
- **AVIF encoding** uses the default speed and all cores through the global pool; cap threads and use a faster speed for thumbnails.
- **Caching gaps.** The WASM bundle endpoint sends `must-revalidate` without an ETag, so every open downloads up to 50 MiB (`features/wasm/api/serve_bundle.rs:60-66`); uploaded S3 objects have no `Cache-Control` although keys are immutable.
- **Smaller items.** i18n startup sync issues 5,200 single-row upserts; bb8 runs `SELECT 1` on every checkout (about seven per blog detail read); an anonymous read after a cache miss commits the Tantivy index; strict Tantivy parsing turns bad queries into logged 500s; `BottomBar` refreshes health on every route change; the superuser upload form preloads for every desktop visitor; host-stats charts rebuild options every second; the CPU ray tracer resets canvas size and all accumulation buffers on every mouse move; block breaker allocates colour strings and gradients per brick per frame; chat history trimming drops the page just loaded.

## Checked and sound

Session tokens are 256-bit, stored as SHA-256, rotated on login, and sent in a `__Host-` Secure HttpOnly Strict cookie. Unsafe methods and WebSocket upgrades require an exact trusted `Origin`; CORS uses the same allowlist. Login and reset use dummy hashes, response floors, and generic errors. OIDC validates PKCE, nonce, issuer, audience, and `at_hash`, and links by issuer and subject only. Markdown renders with Comrak defaults at write time, then DOMPurify; other user text renders as text. Uploads are superuser-only, streamed with byte and pixel limits, and re-encoded to AVIF without EXIF. All SQL uses bound Diesel queries; transactions exclude network work; list endpoints batch related rows. The Squaremap plugin socket is owner-only with bounded requests. CI pins actions by SHA with read-only permissions. xtask spawns processes without a shell.
