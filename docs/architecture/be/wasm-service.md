# WebAssembly service

WebAssembly modules use the `features/wasm` API, service, repository, and domain slice. HTTP handlers only parse bounded multipart input, authorize through the current account, call `WasmService`, and map responses. `WasmRepository` owns all Diesel queries and transactions. The process constructs one `Arc<WasmService>` with one PostgreSQL repository, object-store adapter, and byte-bounded cache.

Bundle input is staged to disk, classified from a bounded prefix, and normalized in blocking work. Decompressed content is limited to 50 MiB and must be either HTML or begin with the WebAssembly magic bytes. Public identity decompression has a fixed process-wide admission limit and fails with 503 instead of queueing blocking work without bound. Thumbnail processing uses the shared fixed image-worker limits. Object upload and database persistence use compensation; superseded, deleted, and failed-compensation thumbnails enter the durable media-cleanup ledger.

The compressed bundle cache retains at most 256 MiB. Startup hydration consumes one newest-first blob per keyset query, stops before evicting a newer hydrated entry, and has a fixed inspection bound. PostgreSQL remains authoritative, and oversized entries are served without cache admission. A fixed striped lock set serializes cache-miss publication with bundle replacement and deletion; pre-invalidation makes cancellation fall back to an authoritative read instead of leaving stale bytes. The legacy unpaginated module-list response is hard-capped at the newest 1,024 rows and projects deleted owners to the public nil-UUID tombstone; a future contract can replace that compatibility cap with a public keyset.

Mutations require an active, non-purged, verified, non-system Younghyun account checked inside the repository transaction. Stable module URLs contain mutable bytes, so responses require revalidation and never use `immutable`. HTML demos receive a response-enforced CSP sandbox and `nosniff`; the frontend iframe grants scripts but not same-origin authority. WebAssembly responses preserve gzip negotiation and the WebAssembly MIME type.
