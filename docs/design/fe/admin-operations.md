# Administration operations UI

`/admin/operations` is lazy-loaded behind both authenticated and superuser route guards. Its Operations link appears in the desktop and mobile administration menus only after account bootstrap confirms both conditions. The page binds one typed `adminOperationsApi` wrapper to generated OpenAPI methods; each panel owns independent loading, error, mutation, and receipt state. GET panels load on mount, but no mutation runs until an administrator explicitly confirms it.

Retention notifications use 25-row keyset pages and replace the visible page instead of accumulating records. Both cursor fields are always sent together, paging stops after 100 client pages, and Next is disabled at a short terminal page. Retry requires confirmation of the notification UUID, account UUID, and localized delivery stage. A retry success or conflict resets the view to page one because retry changes queue ordering.

Unresolved media cleanup displays the backend's oldest-first bounded view. A 100-row warning appears only when the server bound is full; each successful reconciliation removes the row and refreshes the bound so later work becomes visible. The legacy URL is inert text and is copied unchanged into the optimistic request. It is never interpreted as an image, link, bucket, or key. The only admitted bucket is the configured application bucket, shown read-only; the administrator must enter the exact object key and acknowledge that maintenance may delete it. Errors refresh authoritative rows while preserving the immutable URL used for the pending confirmation.

Hard purge accepts a bounded UUID input and requires the exact phrase `PURGE <uuid>` plus an irreversible-action acknowledgement. The receipt treats `profile_cleanup_remaining` as the cleanup authority, reports object and metadata counts, and lists sanitized failures without object URLs. A committed identity purge with remaining cleanup is shown as partial rather than successful completion, so the same UUID can be retried after object-store recovery.

UI text synchronization upserts the English and Korean bundles embedded in the running backend, reloads its bounded RAM cache, and then reloads the browser's active locale. Its returned count is described as loaded cache rows rather than changed translations. An error warns that the database update may have preceded a later cache-refresh failure. Page styles remain in the dedicated `admin-operations.css` and `admin-operations-dialog.css` files; every interface string is present in the typed English and Korean defaults and backend source bundles.
