# Forum frontend

The forum is a separate plain-text discussion surface rather than a reuse of blog comments. Public routes are `/forum` for the recency/search list and `/forum/:topic_id` for topic detail. `/forum/new` and `/forum/notifications` require a signed-in browser session. The top navigation links to `/forum`; topic and notification links use stable UUID paths, with reply notification links adding a reply fragment.

`src/services/contracts/forum.ts` is an exact typed adapter over the frozen Rust request and response DTOs while the generated OpenAPI forum client is refreshed. Its paths, methods, nullable masking fields, cursor objects, moderation enums, and `expected_revision` bodies match the registered backend operations; the generated client can replace only this transport adapter without changing page types or behavior.

The list is a topic table in the shape readers know from classic boards: columns for the topic, reply count, and last activity, with pinned topics in their own group above the latest ones. A row's title link covers the whole row. Topic detail is a thread of numbered posts: an author column, a permalink number, relative times with the exact time on hover, and quiet actions underneath. The opening post is number 1, and the topic author is marked on replies. Moderation forms stay collapsed behind a per-post button, so they cannot outweigh the conversation.

The list owns its complete `(pinned, last_activity_at, topic_id)` cursor, loading state, and at most 200 topic rows. The active search term lives in the `q` URL parameter, so a search can be linked and back restores it. Search is submitted explicitly and resets the cursor; the latest request wins, so an older response cannot replace a newer one. Topic detail owns the ascending `(reply_created_at, reply_id)` cursor and retains at most 500 replies. The notification inbox owns its descending `(created_at, notification_id)` cursor and retains at most 200 notifications. The topic and notification loaders reject overlapping local requests with a non-reactive in-flight guard because Solid 2 signal writes commit on the next microtask. Cursor requests always send every field as a unit and never use offsets.

`GET /api/forum/capabilities` is authoritative for interactive controls. Topic creation and reply composition require `can_post`; moderation controls render only when `can_moderate` is true. Ownership controls additionally compare the current account UUID with the response author UUID. Editing is limited to visible content, deletion remains available for an owner's moderator-hidden content, and all ownership controls disappear after deletion or account-identity masking. Authentication state alone never grants moderation. The backend repeats current database authorization for every protected operation.

Topic and reply edits, soft deletion, and moderation send the response `revision` as `expected_revision`. After every revisioned mutation, including a conflict, the page reloads the authoritative first page so stale controls and revision values are discarded. Soft-deleted items remain in sequence with nullable masked title/body fields. Subscriptions are explicit POST/DELETE operations, and notification read state is changed only by the per-notification POST action.

All titles, bodies, replies, names, reasons, and notification text render as JSX text nodes. No forum component uses HTML injection or Markdown rendering. `utils/forumBody.ts` gives plain text two display conventions and nothing more: lines starting with `>` render as a quote block, and bare `http` or `https` URLs render as links with `rel="nofollow noopener noreferrer ugc"`. Quoting a post inserts those lines into the reply box, drops quotes the post already contained, and caps the quoted text at 2,000 characters. The reply text lives in the topic page so any post can quote into it. Ctrl or Command+Enter submits, and after posting the page scrolls to the new reply. Submit validation mirrors the backend Unicode-scalar, UTF-8 byte, and search-term bounds, including moderation reasons. Native `maxlength` values use twice the scalar limit because browsers count UTF-16 code units; this admits supplementary characters while keeping every field's local state bounded. PostgreSQL and the backend domain types remain authoritative. Forum-specific presentation is centralized in `src/styles/forum.css`; components do not add per-file style blocks.

Forum notifications are a bounded inbox view over the backend's 90-day retention policy. The frontend does not retain notification or forum data outside page memory and does not synthesize unread state. When a notification links to a reply fragment, topic detail follows ascending keysets until it finds that stable reply or reaches the 500-row local cap. This scan is triggered only by an explicit reply fragment, rejects overlapping requests, and remains subject to the same fixed page and memory bounds.
